# AIRBOT 视觉抓取与语音控制操作 SOP

适用目录：`/home/su/graspdemo`

适用功能：RealSense 或普通 USB RGB 相机视觉采集、YOLO 实时积木检测、蓝/绿颜色判定、MobileSAM 自动分割、抓取位姿计算、AIRBOT Play 抓取与放置，以及 FunASR 中文语音指令输入。鼠标选择保留为备用流程。

> 以下实机安全原则适用于 `./run_grasp.sh`；纯仿真请直接按第 10 节执行 `./run_sim.sh`，不会连接真机。首次联调必须关闭“语音识别后直接执行”。GUI 启动时会自动驱动机械臂到配置的观察位，因此启动 GUI 不是离线操作。急停只能使用硬件急停或既有控制器的停止方式，“取消语音”和语音“停止”都不是急停。

### 相机选择

默认配置使用 RealSense：

```yaml
Camera:
  type: realsense
  calibration_type: Realsense
```

普通 USB RGB 相机使用：

```yaml
Camera:
  type: usb_rgb
  calibration_type: UsbCam
```

同时必须修改 `UsbCam` 下对应分辨率的 `intrinsic`、`distortion`、`extrinsic`，以及 `UsbCam.table_z_base`。其中 `table_z_base` 是机械臂基座坐标系下桌面高度，单位为米。RGB 模式通过相机射线与固定桌面平面求交得到抓取位置，不使用真实深度；适用于相机固定、桌面高度固定、积木单层摆放的场景，不适用于堆叠或悬空物体。标定可使用：

```bash
PYTHONPATH=app ./venv/bin/python app/airbot_calibration.py --camera-type usbcam
```

标定输出的内参和手眼外参必须写回 `configs/sam_simplegrasp.yaml` 后再启动程序。普通 RGB 模式仍需要机械臂服务和末端位姿同步，因此不是“插上摄像头即可安全抓取”。

## 2. 5.2.2 软件环境准备

抓取、视觉和语音统一使用项目 `venv`。机械臂服务和 SDK 统一使用 5.2.2 版本。

### 2.1 新机器一条命令安装

将厂商提供的两个 5.2.2 安装包放入项目 `packages/`：

```text
arm_sdk-5.2.2-py3-none-any.whl
airbot-arm_5.2.2_amd64.deb
```

然后执行：

```bash
cd /home/su/graspdemo
./install.sh
```

该命令安装 Ubuntu 录音/Qt 依赖，创建 Python 3.10 `venv`，安装视觉推理、FunASR 和 arm-sdk 依赖，并预下载语音模型。项目也兼容 Python 3.11/3.12；安装脚本默认优先选择系统 Python 3.10。安装包不在 `packages/` 时可在同一条命令中指定：

```bash
./install.sh \
  --sdk-wheel /path/to/arm_sdk-5.2.2-py3-none-any.whl \
  --arm-deb /path/to/airbot-arm_5.2.2_amd64.deb
```

已经安装系统服务时可增加 `--skip-system`。安装后运行 `./run_grasp.sh --check`；该检查不会连接或驱动机械臂。

### 2.2 手动安装主程序服务（仅排障）

```bash
sudo dpkg -i \
  '/home/su/下载/5.2.2软件包/airbot_arm_release/product/x86_64/noble/airbot-arm_5.2.2_amd64.deb'
dpkg-query -W -f='${Version}\n' airbot-arm
```

`dpkg-query` 的预期输出为 `5.2.2`。当前机器已经检测到该 deb 已安装；重复安装同一包一般不需要。注意：你提供的 5.2.2 deb 中，`airbot-arm --version` 实测仍输出 `1.0`，因此判断 deb 版本应以 `dpkg-query` 为准；该现象属于安装包自身的版本字符串，不代表系统仍安装旧版。

本项目按你提供的 `5.2.2` deb 与 wheel 精确固定。本版本的包名、`Controller`、运动接口和 Lease 机制以官方 2026-03-13 的 V5.2 changelog 为依据：<https://docs.discover-robotics.com/document/airbot-play/changelog.html#20260313>。

## 5. 启动系统

使用两个终端。启动前再次确认：运行 GUI 会立即移动到观察位。

### 5.1 终端 A：启动机械臂服务

```bash
cd /home/su/graspdemo
sudo airbot-arm -i can0 -t airbot_play_g2 \
  --address 0.0.0.0:50051 --no-return
```

保持终端 A 运行。官方要求使用 `sudo` 启动服务。`--no-return` 表示停止服务时不自动回零，避免退出终端触发未预期运动；如现场流程明确要求回零，可按规范移除此参数。若服务已在正确端口运行，不要重复启动。可在另一个终端检查：

```bash
ss -ltnp | grep ':50051'
```

### 5.2 终端 B：启动抓取 GUI

```bash
cd /home/su/graspdemo
./run_grasp.sh
```

脚本会固定使用项目的 `venv` 同时启动 GUI 和 FunASR 子进程，无需手动激活环境或设置变量。首次运行前可执行 `./run_grasp.sh --check` 做离线环境检查；这不会连接相机或机械臂。默认麦克风编号为 `11`，临时改用其他设备可执行 `./run_grasp.sh --device 10`，也可以在 GUI 面板中修改。

启动脚本不会自动运行需要 `sudo` 的 `airbot-arm` 服务，终端 A 仍需保持运行。

启动后的正常现象：

1. GUI 打开并显示配置的相机实时画面（RealSense 或 USB RGB）。
2. 机械臂移动到 `observe_pose`。
3. 日志出现“已移动到观察姿态”。
4. 右侧语音面板先显示模型加载，约 8–10 秒后显示“语音模型已就绪”。
5. 实时画面中的积木显示检测框、颜色、检测置信度和颜色覆盖率。

任一动作异常时，不要继续抓取，先按第 9 节排查。

抓取下降高度受 `configs/sam_simplegrasp.yaml` 中的 `AirbotGrasp.min_grasp_z` 硬限制。当前值为修正后现场参考位姿的 Z 值 `0.01338870424854599 m`；预测高度低于该值时会自动抬高到此值。该数值是工具中心在机械臂基座坐标系中的 Z，不是积木高度。现场重新标定时必须关闭自动执行，以 `SLOW` 速度进行单次监督测试。

实时积木候选默认需要连续 3 帧确认，检测框使用指数平滑，短时漏检保持 3 个检测周期，颜色按最近 5 帧投票。对应参数位于 `RealtimeDetection.tracking_*`。语音中的常见同音错词会先校正；若从较长环境语音中提取出唯一白名单口令，界面会要求人工确认，即使勾选自动执行也不会直接动作。

颜色抓取位姿准备超时为 8 秒。运动时先规划到目标上方 10 cm，再直线下降；日志会分别显示“移动到预抓取位”和“直线下降到抓取位”。若某一步失败，程序会停止后续路径，并输出该阶段及目标 position/orientation，便于区分预抓取位不可达和直线下降失败。

机械臂离开观察位后若抓取失败，程序会执行失败恢复：抓取区先打开未确认夹持的夹爪并直线上抬到预抓取位；放置低位失败时先释放物体并上抬到预放置位；随后规划返回初始观察位。若已经夹住物体但尚未到达低位放置区，返回观察位时保持夹爪闭合，避免从高处掉落，并要求人工处理。任何恢复步骤失败都会单独记录，且仍会继续尝试返回观察位。

蓝色和绿色积木使用同一个公共放置位。当前 `place_pose.position` 为 `[0.2512875752470927, 0.20641115004740498, 0.08319538687229266]`。抓取后先直线抬升，再移动到该位置正上方 10 cm 的 `pre_place_pose`，直线下降到公共放置位后松爪，然后直线抬升并返回观察位。

自动夹持使用视觉估算宽度减去 `ArmParams.gripper_grasp_compression`，并通过 `gripper_grasp_effort` 发送夹爪前馈力。程序以 50 ms 周期读取 `eef_pos/eef_vel/eef_eff`；开度受阻或目标附近出现强作用力、速度接近零且电机无故障，连续 3 个样本成立即判定“已夹住”。未接触时会按配置分级收紧两次，每级 3 mm；全部尝试仍未确认时停止抬升和放置。

## 6. 首次现场验证顺序

### 6.1 只测试夹爪

1. 确保夹爪周围没有手、物体或线缆。
2. 不勾选“语音识别后直接执行”。
3. 等待语音模型就绪，点击“开始录音”并说“打开夹爪”；说完停顿约 0.8 秒即自动结束。
4. 核对文字是“打开夹爪”，再点“确认并执行文字指令”。
5. 观察夹爪打开和日志“夹爪已打开”。
6. 用同样流程说“关闭夹爪”，确认夹爪关闭。

重复说“打开夹爪”仍然是打开，不会切换成关闭。

### 6.2 只测试实时视觉，不抓取

1. 把一个蓝色积木和一个绿色积木放入工作区，不要点击颜色抓取按钮。
2. 检查实时画面是否出现 `BLUE BLOCK` / `GREEN BLOCK` 框，右侧计数是否正确。
3. 记录右侧的检测置信度和颜色覆盖率。若颜色不稳定，在不启动抓取的情况下调整 `RealtimeDetection.colors`、`min_color_coverage` 和现场照明。
4. 分别移动积木和暂时移出画面，确认框与数量及时更新，不使用旧目标。

### 6.3 分阶段执行颜色抓取

1. 首次仅放置一个蓝色积木，机械臂选择 `SLOW`，不勾选直接执行。
2. 说“抓取蓝色积木”，核对文字和右侧目标信息后手动确认。
3. 程序会固定同一帧 RGB、相机数据、位姿和检测框，使用 MobileSAM 自动分割；目标过期、分割无效或 RGB 平面坐标无效时不会运动。
4. 持续观察机械臂：打开夹爪 → 目标上方 → 下探 → 闭合 → 抬起 → 放置 → 返回观察位。
5. 蓝色成功后，仅放置一个绿色积木，重复同样的低速验证。
6. 最后放入两个同色积木并发出对应指令，确认界面提示目标不唯一且机械臂不运动。

## 7. 日常操作流程

```text
安全检查
  → 启动 airbot-arm 5.2.2（gRPC 50051）
  → 启动 GUI（自动到观察位）
  → 等待 FunASR 就绪和实时检测稳定
  → 语音“抓取蓝色积木”或“抓取绿色积木”
  → 核对文字与唯一颜色目标，手动确认
  → 观察抓取/放置/返回
  → 等待新的实时检测结果
```

确认多次识别、颜色检测和工作区安全后，才可勾选“高可信识别后直接执行”。弱模糊匹配仍必须人工确认。

## 8. 支持的语音指令

| 类别 | 示例 | 前置条件 | 是否运动 |
| --- | --- | --- | --- |
| 图像采集 | 拍照、捕获图像 | 相机正常 | 否 |
| 位姿预测 | 预测抓取、预测抓取位姿 | 已拍照并正确选择目标 | 否 |
| 完整抓取 | 开始抓取、抓取选中物体、抓取并放置 | 已拍照并正确选择目标 | 是 |
| 蓝色积木 | 抓取蓝色积木 | 实时画面中恰好一个有效蓝色目标 | 是 |
| 绿色积木 | 抓取绿色积木 | 实时画面中恰好一个有效绿色目标 | 是 |
| 夹爪 | 打开夹爪、关闭夹爪 | 抓取线程空闲 | 是 |
| 观察位 | 回到观察位、返回观察位 | 抓取线程空闲 | 是 |

一次只说一条指令。支持将“假爪/甲爪”等已审核错词校正为“夹爪”。否定句、疑问句、转述、多条指令、环境对话和不支持的颜色会被拒绝。

| 麦克风无输入 | 重新执行 `--list-devices` | 换成有输入通道的设备，或清除 `GRASP_VOICE_DEVICE` 使用默认设备 |

| 无法连接机械臂服务 | 对照配置端口并执行 `ss -ltnp \| grep ':50051'` | 确认 CAN、服务进程和端口一致 |

| 识别成功但没有动作 | 看是否等待确认、目标过期/不唯一、分割/深度失败或线程忙 | 查看目标状态与诊断日志；失败时程序不会启动抓取 |
| 分割区域错误 | 右键补背景或中键清除 | 不得继续抓取，重新选择直到区域正确 |
| 预测失败 | 查看日志、深度图和目标是否在有效区域 | 重新摆放物体、拍照、选择；预测失败时程序不会启动抓取 |
| 运动异常或有碰撞风险 | 立即使用硬件急停 | 排除原因前不得重试；“取消语音”不能停止已开始的运动 |

## 10. DISCOVERSE 仿真验证（不连接真机）

详细仿真参数和排障见 [DISCOVERSE.md](DISCOVERSE.md)。仿真停机只需关闭窗口，无需停止机械臂服务。

## 13. 真机运行时同时显示仿真窗口（反馈镜像）

安装仿真依赖后，先启动原有 `airbot-arm` 服务，再执行：

```bash
./install_sim.sh
./run_grasp.sh --with-sim
# 可组合选择麦克风：
./run_grasp.sh --with-sim --device 11
```

这是真机入口，会连接并驱动真实机械臂，启动时仍会移动到观察位。
主窗口正常录音/确认后，只有真机控制入口发送一次动作；独立仿真窗口持续回放实际
关节角和夹爪开度，不再运行另一条独立抓放轨迹。这样真机失败或停住时，不会出现
仿真继续“成功执行”的假象。镜像进程不申请 SDK 控制权，也不向真机发送指令。
关闭仿真窗口不会停止真机，关闭主窗口会清理镜像进程。

积木位置来自真实相机的 YOLO 颜色目标及 RGB-D 点云，通过已有手眼外参转换到真机
基座坐标，再按 `configs/live_mirror.yaml` 的 `world_from_base` 放入仿真。
每种颜色仅接受一个当前可见的目标；同色多目标、深度无效或结果超过 3 秒时隐藏该积木。
顶面完整时显示实色积木；检测有有效深度但顶面尺寸不完整时，显示半透明估计积木，
其位置来自可见点云，不能作为精确中心或抓取依据。被夹持但不可见的物体不会被虚构为跟随夹爪；再次检测到后恢复显示。
当前支持桌面轴对齐方块，尺寸按现场 2.5 cm 配置，姿态没有通过视觉估计；不支持把 USB RGB
平面估计当作可靠三维位置。真实相机持续检测决定是否显示，包括抓放途中。

首次现场对齐必须核验：

1. `joint_signs`、`joint_offsets` 与 SDK 的六关节顺序、弧度、方向和零位一致。
2. 实机 AIRBOT Play G2 与 DISCOVERSE Play 模型几何/TCP 的差异，不能仅凭名称视为一致。
3. 实机手眼外参、RGB-D 内参、单位、相机安装位置；图像与状态由现有采集线程依次读取，
   尚非硬件时间同步，快速运动中可能存在偏差。
4. 配置实测积木尺寸和仿真世界/真实基座变换，在多个静止位置对照尺量并记录误差。

窗口属于**实测反馈的可视化镜像**，并不是两台机器人独立同步执行，也不保证零延迟或
毫米级一致。默认约 15 Hz 更新，状态超过 1 秒不显示。当前未做现场精度验收，不能声称
仿真物体与实物完全重合；遮挡与未知状态会明确提示，不回退到预设积木位置。
离线测试：`PYTHONPATH=app ./venv/bin/python -m unittest -v tests.test_live_mirror`。

### 控制租约失效（no control lease）

若出现 `no control lease, reject: switch_controller`，先查找更早的
`renew_control failed`。SDK 5.2.2 在续租 RPC 失败后会清空本地租约并停止续租线程。
例如 `FAILED_PRECONDITION - no controller` 表示服务端已不认可当前控制租约，
不是 YOLO 位姿计算错误；具体丢失原因还需对照服务端日志。

确认服务正常、没有其他控制程序持有控制权后，在主窗口“手动备用”中的手动控制区
点击“恢复控制连接”。该操作关闭旧控制客户端，建立新客户端并申请租约，只恢复速度
设置，不切换控制器、不移动机械臂、不重放失败任务。等待新检测结果后再确认新指令。
恢复失败会保留无控制连接状态，不自动重试动作。任务执行中禁止重建控制连接。
租约失效时停止后续运动，也不会重新获取租约后自动执行失败恢复路径。

镜像窗口会分别显示蓝/绿积木的基座坐标、测量年龄以及未显示的原因，例如深度点不足、
目标不唯一、检测暂时丢失或数据过期。镜像的 3 秒显示时效不改变真机抓取的 1 秒时效。
真实画面有 YOLO 框只表示二维识别成功；没有有效深度/手眼位姿时不编造三维坐标。

### 积木抓取方向与毫米级偏差排查

SimpleGrasp 默认按 `AirbotGrasp.block_size_m: 0.025` 拟合水平放置的已知立方体。
使用拍摄时的末端位姿及手眼外参恢复相机位置，将分割深度点云同时匹配有限顶面和
朝向相机的侧面，联合求解 XY 中心、顶面高度、绕竖直轴角度。夹爪沿立方体边闭合，
宽度采用已知尺寸。独立仿真场景仍为 40 mm 积木，对应预测配置显式使用 0.04 m。

侧面可见本身不构成异常。顶面部分缺失时，侧面法向位置与已知半边长可以约束中心；
每个水平方向必须有完整顶面跨度或足够面积的可见侧面支持。仅有侧面、严重遮挡、
尺寸不符、拟合残差大、顶面倾斜或存在多个近似等价位姿时拒绝预测，不猜测隐藏位置。
当前采用单帧拟合，未实现多视角融合或自动移动相机。此模型假定积木水平、尺寸已知，
不适用于任意长方体、倾斜摆放和堆叠。没有配置尺寸的兼容路径保留旧顶面矩形算法及其检查。

`runtime/*_geometry.json` 中的 `geometry_fit` 保存算法、尺寸、拟合残差和侧面约束。
残差只衡量点云与模型的一致性，不能测量真实标定误差，也不保证消除实际 4 mm 偏移。
最低抓取高度、55 mm 预张开和下降起点检查继续生效。更新后重启程序（无需重启电脑），
重新检测并核对预测位置；离线测试不代表真机精度验收。若仍有稳定偏差，继续核验内参、
深度、手眼外参与 TCP。

### 重复框与顶面低估

同色检测框 IoU ≥ 0.55，或交集占较小框面积 ≥ 90% 时保留优先级最高的框；
新观测优先于暂存轨迹，其次按置信度选择。分开的同色目标仍要求人工消除歧义。
已知尺寸路径不再采用“顶面边缘偏差超过 4 mm”这一单独阈值，而采用上述表面拟合与
可观测性检查；不会直接用侧面投影边界的中点替代积木中心。

现场积木长宽高为 25 mm，镜像尺寸设为 0.025 m。抓取前最小张开宽度
`ArmParams.gripper_min_open_width` 为 0.055 m（每侧名义余量 15 mm），
实际张开宽度仍按预测宽度与余量取较大值、受夹爪最大行程限制。此设置仅用于
下降前张开，不补偿 XY 坐标，也不取消异常顶面保护；需确保张开路径不碰邻近物体。

### 偏移随夹爪旋转时：先核验实际 TCP

若积木静止、相机观察位相同，抓取偏移方向却随夹爪方向旋转，优先核验夹爪安装、
两指对称性、SDK 末端原点与真实夹持中心的横向偏置，同时排查腕部定位误差。
这不是单凭一次图像就能确认的 TCP 数值；不要直接给基座 X/Y 加固定 4 mm。
固定观察位下，先停止下降，在同一目标上方测量不同夹爪方向（例如 0/90/180 度）
的实际夹持中心。基座坐标下误差随姿态旋转，才支持工具坐标固定偏置模型。
若工具原点到实际夹持中心为 t，目标中心为 p、姿态为 R，则原点应位于 p-Rt；
标定时必须核对 SDK 位姿原点，避免重复计算工具长度。此处未启用未经测量的补偿。

2026-09-24 只读查询 D435i 的 640×480 BGR8/30 配置，设备报告主点约
(320.001, 236.032)、焦距约 (613.410, 612.409)；现有 YAML 为
(318.347, 249.831)、(604.776, 604.659)。深度单位约 0.001 m，与配置一致。
内参差异需要核验；若原手眼标定基于旧内参，应联合复核内参和外参，不能把
直接替换内参当作完整标定修复。

每次成功预测的 runtime/*_geometry.json 保存拍摄时 SDK 位姿、手眼变换、
目标姿态、夹持方向和拟合宽度；配合同名前缀 RGB、深度和 mask 可离线复算。
主窗口记录张开指令与反馈开度、预抓取目标和 SDK 位姿反馈。它们不测量真实
指尖位置；现场仍需外部尺度或标定目标测量。更新代码不会自动采集或移动真机。

预抓取开度余量更新为总宽 30 mm，最小张开宽度 55 mm，仍受 72 mm 最大行程约束。
张开后及预抓取位下降前均读取夹爪反馈：反馈小于指令超过 1 mm、速度绝对值
超过 2 mm/s、反馈非有限数或夹爪报错时停止后续抓取。增大开度不会修正坐标误差，
也不能保证避免碰撞；尤其需要为邻近积木和其他障碍物留出更大的手指扫掠空间。

G2/DM J4310 反馈中的 error_id=1 表示“使能正常”，0 表示失能非故障，
不能把所有非零值当成故障。下降前开度检查复用驱动层状态定义；即便状态码正常，
实际开度不足或仍在运动也会停止抓取。0x08–0x0E 及未知故障仍拦截。

### 下降起点检查

抓取下降在切换到规划控制器后，读取 SDK 实际末端位姿，与上方 100 mm 的
预抓取目标比较。三维位置误差超过 1 mm 或姿态角误差超过 1° 时，不发送下降
指令，也不自动执行恢复路径，保持当前位置并提示人工核验。正常下降速度与加速度
规划比例均限制为至多 0.10（比例，不是 0.10 m/s）。夹爪 55 mm 最小预张开保持不变。
这是起点检查，不是下降过程的实时轨迹监控；不能发现 SDK 未反映的实际指尖偏差，
也不能保证运动中没有跟踪误差。如仍观察到下降横移或旋转，应停止实物抓取并检查
控制器轨迹、末端标定和手眼标定，而不是继续扩大余量或关闭起点检查。

### 立方体拟合残差检查修正

2026-09-24 回放三份已保存真实 RGB-D/mask/拍摄位姿（145642、150041、150102），
旧条件“90% 点在表面 2 mm 内且截断 RMS ≤ 1.5 mm”全部拒绝。
现将表面内点定义为距有限可见面 < 3 mm，要求内点比例 ≥ 75%，且内点 RMS ≤ 1.5 mm；
尺寸、顶面支撑、侧面支撑、倾斜和多解检查仍保留。拟合本身仍使用鲁棒损失，
不以删除大量异常点强制通过。三份记录内点比例约 82%–85%，内点 RMS 约 1.1–1.3 mm，
均通过现有几何检查；没有真实中心标注，不能据此宣称定位精度或碰撞安全已经验收。
新增离群点测试同时验证少量污染下中心/方向误差和大量污染时拒绝。

匹配失败提示包含有效表面比例与残差。启用 RunTime.dump 时，立方体预测失败会保存
`runtime/*_rejected.npz`（基座点云、相机位置、参考方向及尺寸）及同名 JSON 原因/诊断，
便于回放本次失败，而不必依赖之前成功预测的数据。重启程序后生效，无需重启电脑。

### 固定向画面上方偏移的现场补偿

以下为历史调整记录；当前补偿为 `[0.0, 0.0]`，以本节末尾 2026-09-28 回放结论为准。

用户观察：抓取点约向画面上方偏 10 mm，旋转积木后偏移方向不变。
最近五次拍摄变换中画面上方方向在基座系约为 [0.981, 0.005, 0.195]，
因此当前观察位采用 `AirbotGrasp.grasp_offset_base_xy_m: [-0.010, 0.0]`。
该值在几何拟合后加到抓取目标基座 XY，不随积木/夹爪转动；预抓取与下降终点
使用同一补偿目标。Z、夹持方向和放置位保持原计算方式。
